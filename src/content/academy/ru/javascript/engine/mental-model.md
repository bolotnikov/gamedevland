Теперь объединим рассмотренные этапы: **ECMAScript задаёт правила → V8 готовит код → инструкции выполняются → вызовы создают состояние → объекты остаются живы по достижимости**. Среда исполнения дополняет это внешними API.

Особенно важно удержать границы. [AST](https://v8.dev/blog/scanner) не является байткодом. Байткод не является машинным кодом. Стек контекстов из спецификации не обязывает каждую переменную физически лежать на машинном стеке. Наличие GC не отменяет lifecycle. Наличие JIT не обещает мгновенно оптимизированную игру.

Рассмотрим, что происходит при `const enemy = spawnEnemy()`: обработка кода, вызов функции, возвращение объекта и связь из переменной. Затем добавим условие: объект enemy попал в глобальный кэш. Почему завершение функции уже не достаточно для освобождения объекта?

Подсказки на схеме помогут повторить основные механизмы. После этого перейдём к проверке и определим, какие части требуют дополнительного разбора.
