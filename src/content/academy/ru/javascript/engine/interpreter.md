[Интерпретатор](https://v8.dev/docs/ignition) выбирает очередную инструкцию байткода, выполняет её обработчик и переходит дальше. Для программы это может выглядеть как «взяли значение → выполнили операцию → вернули результат».

CPU при этом выполняет машинный код **самого интерпретатора**. Байткод остаётся данными, которые направляют его работу. Поэтому утверждения «интерпретатор не использует машинный код» и «JS просто исполняется построчно» вводят в заблуждение.

У интерпретации есть накладные расходы на выбор инструкций и переходы между обработчиками. Зато не нужно заранее тратить много времени на оптимизацию каждой функции. Это полезно для холодного кода, который выполнится один или несколько раз.

**В игровой сцене** загрузочная ветка и `update()` могут иметь совершенно разные профили исполнения. Одно решение для них не обязательно будет одинаково выгодным.
