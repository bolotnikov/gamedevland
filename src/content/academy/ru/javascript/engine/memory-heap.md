Объект игрока должен существовать, пока программа может к нему обратиться. Движок выделяет для него память и организует доступ к свойствам. **[Memory heap](https://v8.dev/blog/trash-talk)** — привычное название области управляемой памяти объектов.

```js
const player = { hp: 100 };
const target = player;
target.hp = 80;
// player.hp is also 80
```

`target` не получает автоматически копию объекта. Оба имени позволяют обратиться к одной и той же идентичности. На схеме стрелки показывают эту связь, а `object #1` — учебная метка, не адрес памяти V8.

Правило «все примитивы на стеке, все объекты в куче» слишком грубое. Спецификация описывает значения и поведение объектов, но не требует конкретного физического хранения. Оптимизатор вообще может устранить некоторые выделения памяти, если наблюдаемое поведение сохранится.

Для архитектуры игры полезнее вопрос: **кто удерживает объект и когда должен перестать его удерживать?**
