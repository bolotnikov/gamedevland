В предыдущем уроке мы рассмотрели, как [Ignition](https://v8.dev/docs/ignition) выполняет байткод: читает инструкцию, выбирает обработчик и переходит дальше. Чтобы сократить расходы на эти действия, V8 может создать машинную версию функции. При её выполнении уже не требуется выбирать обработчик каждой инструкции байткода.

<aside class="lesson-note" aria-labelledby="jit-note-title">
  <span class="lesson-note__label">Термин</span><h3 id="jit-note-title">JIT-компиляция</h3>
  <p><strong>Just-in-time compilation</strong> — создание машинного кода во время работы программы. После компиляции CPU может выполнять машинную версию функции.</p>
  <p>Оптимизация дополнительно сокращает лишнюю работу в коде, сохраняя поведение программы. Чем сложнее преобразования, тем больше времени может потребоваться на компиляцию.</p>
</aside>

Если функцию вызовут один раз, длительная оптимизация может не окупиться. Для функции, которая регулярно выполняет много работы, затраты на компиляцию могут окупиться ускорением последующих вызовов. Поэтому в V8 есть несколько компиляторов с разными задачами.

**Ignition — интерпретатор. Sparkplug, Maglev и TurboFan — компиляторы в составе того же V8.** Сравним их роли:

<dl class="jit-comparison" aria-label="Сравнение интерпретатора и компиляторов V8">
  <div class="jit-comparison__card tone-cyan">
    <dt><span>Интерпретатор</span><a href="https://v8.dev/docs/ignition">Ignition</a></dt>
    <dd>Выполняет байткод через обработчики. Отдельная машинная версия функции для этого не нужна.</dd>
    <dd class="jit-comparison__purpose">Позволяет начать выполнение без JIT-компиляции функции.</dd>
  </div>
  <div class="jit-comparison__card tone-green">
    <dt><span>Быстрый компилятор</span><a href="https://v8.dev/blog/sparkplug">Sparkplug</a></dt>
    <dd>Быстро переводит байткод в машинный код без сложной оптимизации.</dd>
    <dd class="jit-comparison__purpose">Сокращает расходы интерпретации при небольших затратах на компиляцию.</dd>
  </div>
  <div class="jit-comparison__card tone-violet">
    <dt><span>Оптимизирующий компилятор</span><a href="https://v8.dev/blog/maglev">Maglev</a></dt>
    <dd>Учитывает наблюдения о работе функции, например о типах значений, чтобы создать более быстрый машинный код.</dd>
    <dd class="jit-comparison__purpose">Тратит больше усилий на оптимизацию, чем Sparkplug, но рассчитан на более быструю компиляцию, чем TurboFan.</dd>
  </div>
  <div class="jit-comparison__card tone-amber">
    <dt><span>Оптимизирующий компилятор</span><a href="https://v8.dev/docs/turbofan">TurboFan</a></dt>
    <dd>Применяет более сложные оптимизации, стремясь получить быстрый код для функций, на выполнение которых программа тратит много времени.</dd>
    <dd class="jit-comparison__purpose">Более дорогая компиляция может окупиться при длительном выполнении функции или её повторных вызовах.</dd>
  </div>
</dl>

<aside class="lesson-note is-green" aria-labelledby="execution-tier-note-title">
  <span class="lesson-note__label">Термин</span><h3 id="execution-tier-note-title">Уровень выполнения (tier)</h3>
  <p>Вариант выполнения функции: интерпретация байткода или машинный код, созданный одним из компиляторов. «Верхний уровень» в этом сравнении — оптимизация TurboFan.</p>
</aside>

**V8 принимает решение для каждой функции отдельно.** Функция не обязана проходить все перечисленные уровни. Конкретный выбор зависит от версии и настроек движка, а также от наблюдений за выполнением программы.
