Понимание V8 нужно, чтобы выбирать проверяемые гипотезы. Медленный старт — повод посмотреть объём поставки, parse/compile и инициализацию. Дорогой `update()` — найти конкретную функцию и структуру работы. Рост памяти между сценами — исследовать удержание объектов.

**Это разные симптомы.** Переписывание объектов ради «правильных hidden classes» не обязано исправить сетевой старт. Object pool не устранит listener, который продолжает держать старую сцену.

Для эксперимента зафиксируем устройство и сценарий, запишем [профиль](https://developer.chrome.com/docs/devtools/performance), изменим один существенный фактор и сравним результат. При этом нужно учитывать прогрев: первый запуск и установившееся выполнение отвечают на разные вопросы.

Для каждого симптома в панели указан следующий шаг диагностики. Приведённые величины иллюстративны: это не результаты benchmark и не гарантия ускорения. Цель — связать механизм с наблюдаемым поведением HTML5-игры.
