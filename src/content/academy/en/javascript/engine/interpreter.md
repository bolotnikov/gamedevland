In the previous lesson, we generated bytecode from an AST. Now **[Ignition](https://v8.dev/docs/ignition)** reads that bytecode and performs the specified operations one at a time.

Each instruction has a **handler**: the part of the interpreter that performs its operation. The CPU executes the machine code of Ignition's handlers.

<aside class="lesson-note" aria-labelledby="accumulator-note-title">
  <span class="lesson-note__label">Term</span><h3 id="accumulator-note-title">Accumulator</h3>
  <p><a href="https://v8.dev/blog/ignition-interpreter#details">A place where the interpreter stores the current intermediate result.</a> The next instruction can use or change this value.</p>
</aside>

Consider the function `add(a, b)`, which returns the sum of its arguments. When called as ` add(2, 3)`, its instructions first load `2`, then add `3`, and return `5`.
