# Site localization

## Contract

English pages keep existing unprefixed URLs; Russian equivalents use `/ru/`.
At `https://gamedev.land/`, the client selects the saved language, then the first supported
browser language, with EN as the fallback. Automatic and manual choices are stored under
`gamedevland:locale:v1`. A regional preference such as `ru-RU` selects RU.
Explicit language URLs remain directly addressable; switching language uses an ordinary
link to the corresponding page and preserves query parameters and the fragment.
If storage is unavailable, EN is the fallback and ordinary language links still work. Static HTML,
canonical URLs, and x-default remain English at `/`. Alex authorized this behavior and
its production release on 2026-11-08.

The home page lists GameDevLand SDK, Cyber UI Toolkit, and Advanced JavaScript, in that order.
The former `/academy/` catalog redirects to `/` (and `/ru/academy/` to `/ru/`).
There is no separate Academy navigation item. Cyber UI has one section, so its course root
shows the lesson list; the former `/academy/cyber-ui/interface/` overview redirects there.
Individual lesson URLs and progress IDs retain the `interface` segment.

Beside the theme control,
the language dropdown shows only the current locale's label when closed. Its links switch to the
same page and preserve the fragment; options come from the shared locale registry.

## Authoring order — latest agreement

Write and revise public-facing content in Russian first, including diagram text, exercises,
and lesson feedback. Alex reviews the Russian version. Only a separate explicit request
after approval authorizes creating/updating English versions; approval by itself does not.
Do not translate each intermediate revision or automatically keep English drafts synchronized.
Existing English pages remain in place while the Russian material is being reviewed.

This supersedes simultaneous EN/RU authoring instructions, while retaining English at `/`.
The current route manifest and locale checker enforce complete published language pairs.
Those checks are release constraints, not authorization to translate a Russian draft. For
new Russian-only content, adapt local preview/staging narrowly when needed, without fake
English text, automatic translation, or publishing unfinished translations. This workflow
update itself does not change routes or delete any existing translations.

## Services

The services overview at `/services/` and its six landing pages are published in English
and Russian through the shared catch-all route. Internal links use `Locale.path()`;
the language switch preserves the service and fragment. `ServiceCatalog` resolves the
shared definitions in `src/data/services.ts` through the registered message catalogs.
Diagrams, image descriptions, contact subjects and UI labels use the same locale.

## Sources and rendering

- `src/i18n/locales.ts`: locale codes, prefixes, native labels, date locales; the default is EN.
- `src/i18n/Locale.ts`: locale resolution, URL generation, interpolation, validated message lookup.
- `src/i18n/messages/<locale>.json`: authored UI/simulation/feedback translations. Message keys
  are normalized source strings; values are the complete text in the target language.
- `src/content/{articles,games,tutorials,academy}/<locale>/...`: separate Markdown sources.
  Each file has a locale and stable translationKey shared by its translations.
- `src/pages/[...path].astro`: a single static route manifest for all locales.
- `src/views/`: shared page templates; `src/components/`: shared components.
- `src/i18n/Content.ts`: locale-scoped content queries.

The content schema validates locale metadata and official Academy sources. Route generation
checks complete, unique translation identities. Message lookup throws if a translation is
missing; the site never silently substitutes another language.

Article catalog records for tutorial series contain metadata. Their actual content lives in
`tutorials`, one file per chapter. The previous unused monolithic bodies were preserved in
`drafts/legacy-articles/`. An older unpublished Russian AI article was kept in
`drafts/legacy-translations/`; the published Russian page translates the current English article.

## URLs and page metadata

Examples:

| English | Russian |
| --- | --- |
| `/` | `/ru/` |
| `/services` | `/ru/services` |
| `/games/idle-submarine` | `/ru/games/idle-submarine` |
| `/articles/runner/creating-a-hero` | `/ru/articles/runner/creating-a-hero` |
| `/academy/javascript/engine/call-stack/` | `/ru/academy/javascript/engine/call-stack/` |

Use `Locale.path()` for internal navigation; leave resource paths and external links unchanged.
Both language versions link technical terms to the same official sources. Astro's shared
Markdown pipeline parses authored HTML and adds `target="_blank"` with
`rel="noopener noreferrer"` to external HTTP(S) links at build time. Internal links and
fragments retain normal navigation. Direct Astro anchors declare those attributes explicitly.
The Layout generates localized canonical links, alternates for all locales, x-default pointing
to English, and Open Graph locale metadata. Sitemap locale definitions use the same registry.
Dates use the locale's Intl format and UTC for date-only publication values.

Translated Markdown headings include cross-language anchor aliases where needed. The language
switch preserves the current fragment. Table-of-contents code decodes non-ASCII fragments.

## Shared browser state

Theme preference has one global key. Lesson completion, current step, quiz choices, and answer
drafts use the existing language-independent lesson key. Switching language preserves them.
Reader-authored answers are never translated automatically. Simulation state is transient and
starts at the first state when a different page is loaded.

## Translation discipline

In the separately authorized translation task, translate prose, metadata, diagrams, alt text,
labels, source notes, and client feedback from the approved Russian version.
Keep fenced code blocks byte-for-byte equivalent, preserve identifiers and numbers, keep
source URLs, and preserve the distinction between normative semantics and teaching models.
Proper game/library names and source-code tokens retain their original form. Official linked
source documents and externally embedded media retain their original language.

Do not translate source files using blind whole-file replacements: code, paths, and tags are
not prose. Review translation segments in context. Use UTF-8-aware offsets when authoring tools
parse HTML with byte positions; Markdown tooling may report UTF-16 offsets instead.

## Adding another language

1. Add its code, prefix (e.g. `/es`), native name/label, and Intl date locale to `locales.ts`.
2. Create its full message catalog with the same keys as existing catalogs.
3. Create equivalent Markdown files for every active content key, with the new locale metadata.
4. Preserve code, source URLs, lesson IDs, and data contracts; add heading aliases as needed.
5. Run the checks below, then review the new language's layouts and interactions locally.

No page template, navigation branch, or theme implementation needs to be copied. A missing
language/content pair fails validation instead of producing a mixed-language page.

## Verification

```sh
npm run typecheck
npm run lint
npm run build
npm run check:locales
```

`check:locales` verifies message-key parity, complete content file pairs, unchanged fenced code,
and valid generated alternate links. Review ordinary internal links and language switches,
translated section anchors, narrow/wide layouts, both themes, and persisted quiz/draft state.
